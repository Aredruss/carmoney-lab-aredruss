# Intent: MILEAGE — пробег авто не больше 400 000 км, иначе решение review

Лог интервью Grill Me: `grill_MILEAGE.md` (2026-09-24).

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега автомобиля: «пробег авто не
больше 400 000 км, иначе решение review» (ответ в интервью — исходная формулировка
заказчика). Решение по заявке остаётся одним из трёх: `approve` / `review` / `reject`
(код: backend/src/Domain/DecisionEngine.php); проверка добавляется к существующему
расчёту решения.

## 2. Зачем

Сейчас на решение влияет только LTV: в расчёт решения передаётся единственное число,
пороги 60.0 / 85.0 % (код: backend/src/Domain/DecisionEngine.php; код:
backend/config/rules.php). Пробег входит в заявку и проходит валидацию, но на решение
не влияет (код: backend/src/Domain/ApplicationValidator.php). Проверка закрывает этот
пробел: заявка с пробегом выше порога не должна получать автоматическое решение только
по LTV — ей назначается `review` (ответ в интервью — исходная формулировка).

## 3. Constraints

- Порог правила — 400 000 км, формулировка: «не больше 400 000 км, иначе решение
  review» (ответ в интервью). Точная граница порога формулировкой не определена —
  см. Open questions №1.
- Проверка добавляется к существующему расчёту решения по LTV; пороги LTV не меняются:
  до 60 % (не включая 60) — `approve`, 60–85 % — `review`, свыше 85 % — `reject`
  (код: backend/config/rules.php; код: backend/src/Domain/DecisionEngine.php).
- Пробег в заявке — целое число от 0 до 500 000 км; вне диапазона, отсутствует или
  `null` — ошибка валидации, решение не рассчитывается
  (код: backend/src/Domain/ApplicationValidator.php; число 500 000 —
  код: backend/config/rules.php).
- Пустая строка в поле пробега сегодня приводится к 0 и проходит валидацию
  (код: backend/src/Domain/ApplicationValidator.php).
- Заявки с пробегом свыше 500 000 км остаются ошибкой валидации и под новое правило
  не попадают: «иначе review» действует только на пробеги, прошедшие валидацию
  (ответ в интервью, вопрос 4).
- Новых исходов правило не вводит: решение по-прежнему только `approve` / `review` /
  `reject` (код: backend/src/Domain/DecisionEngine.php).

## 4. Open questions

1. Граница порога 400 000 км: 400 000 включительно (review с 400 001) или 400 000 уже
   даёт review. Статус: открыт. Владелец: бизнес-аналитик (назначен заказчиком
   в интервью).
2. Неуказанный пробег: сохранить текущее поведение (отсутствует/`null` — ошибка
   валидации, пустая строка — приводится к 0) или отклонять и пустую строку как
   ошибку. Статус: открыт. Владелец: системный аналитик (назначен заказчиком
   в интервью).
3. Сочетание с `reject`: буквальное чтение «иначе решение review» переводит в review
   любое решение, включая `reject` по LTV; альтернатива — правило только ужесточает
   (`approve` → `review`), `reject` сохраняется. Статус: открыт. Владелец:
   бизнес-аналитик (назначен заказчиком в интервью).
4. Пробег свыше 500 000 км — ошибка валидации или review. Статус: закрыт заказчиком
   в интервью 2026-09-24, вопрос 4: остаётся ошибкой валидации.
5. Включать ли в объём скидки за пробег из CASE-08. Статус: закрыт заказчиком
   в интервью 2026-09-24, вопросы 5–6: убрано из объёма.

## 5. Не входит

- Скидки за пробег при расчёте залоговой стоимости (CASE-08) — ответ в интервью,
  вопросы 5–6.
- Возрастные лимиты при расчёте решения (LOAN-12) — ответ в интервью, вопрос 5:
  не выбрано.
- Маркировка причины review в ответе по заявке (материал для журнала LOAN-15) —
  ответ в интервью, вопрос 5: не выбрано.
- Изменение границы валидации пробега 500 000 км и перевод пробегов свыше неё
  в review — ответ в интервью, вопрос 4.
- Правки фронтенда — ответ в интервью, вопрос 6: объём ограничен правилом пробега.
