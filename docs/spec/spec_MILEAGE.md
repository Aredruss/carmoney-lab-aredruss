# Spec: MILEAGE — пробег авто не больше 400 000 км, иначе решение review

Источник требований: `docs/intent/intent_MILEAGE.md` (интервью Grill Me 2026-09-24,
`docs/intent/grill_MILEAGE.md`). Спека отвечает на вопрос «что считается сделанным»,
не «как реализовывать» (это `docs/plan/plan_MILEAGE.md`).

## 1. Входит / не входит

Входит:

- Проверка пробега в расчёте решения по заявке: пробег выше порога переводит
  решение в `review` (intent §1).
- Порог проверки — 400 000 км (intent §1, ответ заказчика в интервью).
- Взаимодействие правила с существующим расчётом решения по LTV (intent §3).
- Поведение при пустом и неуказанном пробеге (intent §3, Open question №2).

Не входит:

- Скидки за пробег при расчёте залоговой стоимости, CASE-08 (intent §5;
  интервью, вопросы 5–6).
- Возрастные лимиты при расчёте решения, LOAN-12 (intent §5; интервью, вопрос 5).
- Маркировка причины review в ответе по заявке, LOAN-15 (intent §5; интервью,
  вопрос 5).
- Изменение границы валидации пробега 500 000 км и перевод пробегов свыше неё
  в review (intent §5; интервью, вопрос 4).
- Правки фронтенда (intent §5; интервью, вопрос 6).

## 2. Требования

Требования атомарны и проверяемы. Числа: 400 000 — формулировка заказчика
в интервью (intent §1); 500 000 — `backend/config/rules.php` `vehicle.max_mileage_km`;
60.0 / 85.0 — `backend/config/rules.php` `ltv.approve_max` / `ltv.review_max`.
Пометка `[OQ-N]` — требование зависит от открытого вопроса №N (раздел 4).

- **REQ-MILEAGE-01.** Заявка, чей пробег прошёл валидацию (целое число
  от 0 до 500 000 км), при пробеге больше 400 000 км получает решение `review`.
  Источник: intent §1, §3; числа: 400 000 — интервью, 500 000 — rules.php.
- **REQ-MILEAGE-02 [OQ-1].** Заявка с пробегом 400 000 км включительно
  не переводится в `review` по правилу пробега (рабочее допущение —
  включительная граница; при смене решения бизнес-аналитика AC-MILEAGE-02
  и AC-MILEAGE-03 меняются местами по смыслу). Источник: intent §3,
  Open question №1.
- **REQ-MILEAGE-03 [OQ-3].** Правило применяется поверх любого решения по LTV,
  включая `reject`: заявка с LTV > 85 % и пробегом выше порога получает `review`
  (рабочее допущение — буквальное чтение «иначе решение review»). Источник:
  intent §1, Open question №3.
- **REQ-MILEAGE-04 [OQ-2].** Пробег, отсутствующий в заявке или равный `null`,
  — ошибка валидации, решение не рассчитывается (текущее поведение валидатора).
  Источник: intent §3; Open question №2.
- **REQ-MILEAGE-05 [OQ-2].** Пустая строка в поле пробега приводится к 0
  и проходит валидацию (текущее поведение валидатора; заявка с таким пробегом
  под правило пробега не попадает). Источник: intent §3; Open question №2.
- **REQ-MILEAGE-06.** Пробег вне диапазона 0–500 000 км — ошибка валидации;
  такие заявки до правила пробега не доходят. Источник: intent §3; интервью,
  вопрос 4; число 500 000 — rules.php `vehicle.max_mileage_km`.
- **REQ-MILEAGE-07.** Правило пробега не вводит новых исходов: решение
  по-прежнему только `approve` / `review` / `reject`. Источник: intent §3.
- **REQ-MILEAGE-08.** Пороги решения по LTV не меняются: LTV < 60 % —
  `approve`, 60–85 % — `review`, свыше 85 % — `reject`. Источник: intent §3;
  числа — rules.php `ltv.approve_max`, `ltv.review_max`.

## 3. Критерии приёмки

Формат Given / When / Then. Граница правила — 399999 / 400000 / 400001,
граница валидации — 0 и 500000. Контекст всех AC: валидная заявка,
при которой без правила пробега решение было бы `approve` (LTV < 60 %),
если явно не указано иное.

- **AC-MILEAGE-01** (REQ-MILEAGE-01): Given заявка с пробегом 399999 км
  и LTV < 60 %; When рассчитывается решение; Then решение `approve`.
- **AC-MILEAGE-02 [OQ-1]** (REQ-MILEAGE-01, REQ-MILEAGE-02): Given заявка
  с пробегом 400000 км и LTV < 60 %; When рассчитывается решение;
  Then решение `approve` (граница включительна по рабочему допущению).
- **AC-MILEAGE-03** (REQ-MILEAGE-01): Given заявка с пробегом 400001 км
  и LTV < 60 %; When рассчитывается решение; Then решение `review`.
- **AC-MILEAGE-04** (REQ-MILEAGE-01): Given заявка с пробегом 500000 км
  (верхняя граница валидации) и LTV < 60 %; When рассчитывается решение;
  Then решение `review`.
- **AC-MILEAGE-05** (REQ-MILEAGE-06): Given заявка с пробегом 500001 км;
  When заявка подана; Then ошибка валидации, решение не рассчитывается.
- **AC-MILEAGE-06** (REQ-MILEAGE-06): Given заявка с пробегом −1 км;
  When заявка подана; Then ошибка валидации, решение не рассчитывается.
- **AC-MILEAGE-07 [OQ-2]** (REQ-MILEAGE-04): Given заявка без поля пробега;
  When заявка подана; Then ошибка валидации, решение не рассчитывается.
- **AC-MILEAGE-08 [OQ-2]** (REQ-MILEAGE-04): Given заявка с полем пробега
  `null`; When заявка подана; Then ошибка валидации, решение
  не рассчитывается.
- **AC-MILEAGE-09 [OQ-2]** (REQ-MILEAGE-05): Given заявка с полем пробега `''`;
  When заявка подана; Then валидация проходит (пробег трактуется как 0),
  решение `approve` при LTV < 60 %.
- **AC-MILEAGE-10 [OQ-3]** (REQ-MILEAGE-03): Given заявка с пробегом 400001 км
  и LTV > 85 %; When рассчитывается решение; Then решение `review`,
  а не `reject` (буквальное чтение по рабочему допущению).
- **AC-MILEAGE-11** (REQ-MILEAGE-03, REQ-MILEAGE-08): Given заявка с пробегом
  400001 км и LTV 60–85 %; When рассчитывается решение; Then решение `review`.
- **AC-MILEAGE-12** (REQ-MILEAGE-07): For any AC-MILEAGE-01–11 итоговое решение
  принадлежит множеству {`approve`, `review`, `reject`} и ничего больше.
